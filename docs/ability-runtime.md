# 클래스 런타임 계약과 수정 내역

2026-09-04의 `game-class-structure-review.md`에서 지적한 9개 항목을 대상으로 수정했다.

## 수정 범위

| 검토 항목 | 적용한 변경 |
| --- | --- |
| 1. 작업·효과 종료 | 배정 인스턴스별 `AbilityScope`와 `ResourceScope`. 예약 작업, 표시 엔티티, 공격 가능 오브젝트, 속성 기여분, 행동 제한과 자기 상태의 정리를 연결했다. `PatAndMatt` 제한 해제와 `Tour` 귀환은 취소에도 실행한다. 세션 레지스트리는 클래스 종료 훅으로 정리한다. |
| 2. 재접속 | 클래스·스킬·패시브·원소 런타임이 현재 `PlayerData.player`를 조회한다. 일반 작업은 접속 해제 중 정지하고 재접속 후 남은 틱부터 재개한다. 능력 트리 전체를 다시 연결하며 최초 전투 초기화는 반복하지 않는다. 취소된 이동 효과의 오프라인 대상은 재접속 시 귀환한다. |
| 3. 복합 클래스 | `AbilityTree`가 직접 클래스, 도굴한 클래스, 태양계 행성의 초기화·이벤트·종료를 공통 처리한다. 스킬은 실제 소유 클래스에 연결된다. 무기 입력은 해당 무기의 소유자에게만 전달하고, 도굴한 전용 무기도 지급한다. 직접 행성과 태양계 복사본의 중복 방지 정책을 유지한다. |
| 4. 중첩 속성·제한 | `ScalarModifiers`/`AttributeEffects`로 기본값과 효과별 기여분을 분리한다. 난쟁이·명왕성·오류·유령·저격수·파멸의 일격 및 이동·공격 속도 상태를 연결했다. `ControlLocks`/`ControlLease`로 행동 제한을 합성하며, 팬텀·박쥐·기차·재판·숨바꼭질도 자기 제한만 해제한다. |
| 5. 시간·일시정지 | 클래스 효과의 경과 시간과 쿨다운은 `Game.combatTick`을 사용한다. `AbilityRunnable`의 일반 효과는 경기 정지·접속 해제·하위 능력 비활성화를 준수한다. 재판/숨바꼭질 진행은 `SESSION`, 사망 후 폭탄은 `AFTER_DEATH` 정책으로 분리했다. 재접속 유예는 서버 시간으로 유지한다. |
| 6. 실행 결과 | 모든 스킬은 실행 성공 여부를 반환하며, 실패에는 쿨다운과 성공 후 관찰 이벤트를 적용하지 않는다. 대상·배치 준비값은 `SkillContext`에 저장하고 승인 거부·실패·예외 후 폐기한다. 실행 도중 재진입과 승인 콜백에서 제거된 능력의 실행도 차단한다. |
| 7. 식별·출처 | 고정 `classId`, `definitionId`, 배정 UUID를 도입했다. `AbilityCatalog`가 명시적인 생성자를 제공하며 도굴은 리플렉션으로 복원하지 않는다. 기존 설정 키를 유지하고 JVM 이름으로 기록된 기존 아이템도 조회한다. 핸들러·작업·상태·채팅/선택 콜백은 명시적으로 연결된 출처를 사용하며 스택 추론을 제거했다. |
| 8. 책임 분리 | 수학자의 문제/정답 생성은 `MathProblemGenerator`, 심판관의 진술 선택 규칙은 `DefenseCatalog`, 이기어검의 비행 상태·궤적 계산은 `SwordFlight`로 분리했다. 공통 자원·시간·대상·속성 책임은 `ability` 패키지로 이동했다. |
| 9. 대상 검색 | `Targeting`이 월드·생존·접속·대상 지정·적대 관계·소유 소환체 판정을 공유한다. 훈련 엔티티 등록은 세션 갱신에서 처리하고 조회 함수는 경기 목록을 변경하지 않는다. 반경 조회는 UUID 인덱스를 사용한다. 오브젝트 타격은 명시적으로 요청한 공격에만 적용한다. |

## 새 클래스를 추가할 때

- 이름이나 파일명 변경과 무관한 `classId`와 각 스킬의 `definitionId`를 정하고 `AbilityCatalog`에 생성자를 등록한다. 활성 클래스 목록은 기존 배정 정책을 따른다.
- 하위 능력은 `childAbilities`로 노출한다. 부모가 같은 스킬 객체를 아이템 목록에 노출해도 소유자는 하위 능력이며 이벤트는 한 번 전달된다.
- 예약 효과는 `AbilityRunnable(abilityScope)`를 사용한다. 위치 복귀나 제한 해제처럼 취소에도 필요한 동작은 `onCancel()` 또는 `abilityScope.resources.own { ... }`에 등록한다.
- 외부 콜백에서 효과를 시작하면 `AbilityExecution.with(owner.abilityScope) { ... }`로 소유자를 연결한다. 새 클래스/플레이어마다 런타임 인스턴스를 만들어야 한다.
- 임시 속성은 `attributeEffects.multiply`/`walkSpeed`, 영구 기본값 변경은 `changeBase`를 사용한다. 직접 과거 값을 저장해 복원하지 않는다.
- `isUseSuccess()`는 준비·검증만 수행한다. 실제 자원 소비와 효과 생성은 `use(): Boolean`에서 처리한다. 발사 후 빗나감은 정상 사용으로 간주한다.
- 일반 투사체·장판은 대상을 찾을 때 은신 포함 여부와 자기 자신 포함 여부를 명시한다. 훈련 대상은 시작 시와 초 단위 세션 갱신에서 등록된다.

## 검증

- Gradle 실행 JDK: 설치된 Microsoft OpenJDK 21. 기존 플러그인 JVM 대상 25는 유지했다.
- `gradlew.bat build --offline --console=plain`: Kotlin 컴파일, 전체 38개 테스트, Shadow JAR 생성 및 필수 런타임/컴파일 클래스 포함 검증 통과.
- 테스트는 자원 중복 해제, 작업 취소·일시정지·재접속, 복합 능력 소유/전달/종료, 스킬 승인 취소와 실패, 공유 상태 수명, 속성 제거 순서, 행동 제한 중첩, 쿨다운 정지, 대상 조회 순수성, 수학 문제와 진술 선택, 궤적 계산을 확인한다.
- 기존 피해 배율 테스트는 시작 아이템 생성을 제외해 서버 레지스트리 없이 배율 계산 자체를 검증하도록 조정했다.

실제 Paper 서버의 전투·이동·패킷 동작과 성능 부하 시험은 수행하지 않았다. 서버 확인에서는 이기어검/프리즘 교체, 패트와 매트/순회공연 중 시전자 사망·접속 해제, 도굴한 포탈건·뇌운술사, 태양계와 직접 행성의 조합, 재판 도중 효과/쿨다운 정지, 사망 후 폭탄을 우선 확인한다.
